# Finance authoring previews

Status: REVIEW. This is a bounded presentation change. It does not certify Finance or Reports as U4/U5.

## Scope

Quick actions and table Create buttons use the same preview components. The shared
`FormModal`, `RuntimeFormModal`, and `ModuleView` accept an optional preview. The
preview receives the actual form values, including defaults, edits, reset, and
applied AI suggestions. Forms without a preview retain their existing width.
Example inputs do not submit the record when the user presses Enter.

| Action | Implemented behaviour | Current limit |
| --- | --- | --- |
| New metric | Business measure choices, calculation choices, target, company, and KPI/empty-chart card | Saves a definition. No automatic computation or refresh job is created. |
| Generate report | Document structure, period, comparison and debit/credit columns | Amounts are generated by the existing report service. |
| New template | Page orientation, margins, header/footer lines, escaped title | A4 layout reference. Template body editing remains separate. |
| Schedule report | Selected next run, browser time zone, recipients, format, active state | Does not infer later scheduler run dates. |
| New dashboard | Named empty canvas and next step | Drag/resize authoring is not added. |
| New widget | Finance source selection, count-based charts, grouping/style, existing live renderer and source-quality states | Widget attachment remains a separate existing action. |
| Invoice/bill | Edit document and Document preview tabs use the same line draft, company, currency, taxes and totals | Server confirms amounts and rounding on draft save. |
| Journal header/line | Draft structure and proposed debit/credit totals for the exact loaded company draft | Header creation does not create lines. Posting remains a separate action. |
| Tax | Editable sample amount with included/excluded percentage example | Examples are not saved. Fixed/division taxes require invoice calculation. |
| Payment terms/lines | Empty schedule explanation and sample instalment amount/date | Simple day offsets only. Month/end-of-month/balance rules require the complete schedule. |

Existing `CreateInvoiceModal` and `BudgetsWorkspace` remain the editing owners.
Reconciliation, asset/depreciation workspaces, period-close checklist, full template
body editing, dashboard drag/resize, and executable metric computation remain
separate tasks.

## Authority and scope

Reports: `reports-client.tsx` → existing query hooks in `hooks/reports.ts` → generated
named operations → existing trusted API route → `analytics/reports.rs` and
`analytics/dashboards.rs` → existing result/readback handling. No operation or schema
is added. Widget grouping, chart style, and company domain now survive the existing
form payload mapper. Both the preview and saved renderer apply the selected-company
domain. Preview reads also reject rows outside the organization/company scope.

Accounting: `accounting-client.tsx` → existing Accounting application/query hooks
and generated operations → trusted API routes → existing Accounting reducers.
Manual invoice save retains its company/idempotency-key exact-effect readback,
unknown-outcome recovery, and result navigation. Preview controls perform no writes.

The pre-existing metric/template/schedule/dashboard create hooks have readback limits.
Financial-report creation also retains its pre-existing max-ID/name lookup. This PR
does not replace those paths or claim canonical create certification for them.

## Validation

- Focused unit, React component, and static-render tests cover form state, reset,
  failed saves, preview keyboard input, invoice draft preservation, escaping,
  numeric/date examples, exact draft identity, and saved/preview widget company scope.
- Frontend type checking, production build, translation checks, opaque-record
  ratchet, and browser operation-transport checks are recorded in the PR.
- `frontend/web/tests/e2e/finance-authoring.spec.ts` adds read-only operator checks
  for both metric entry points, report/template/schedule previews, tax interaction,
  and a narrow viewport.
- Local operator execution stopped in `auth.setup.ts`: the available local API
  returned HTTP 500 during sign-in. The preview tests did not execute. A seeded
  same-head browser run and CI remain required before acceptance.
